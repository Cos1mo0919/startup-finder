## Точное повторение команд Codespace

В отдельную пустую SQLite-базу выполнены команды пользователя, с пустыми
API-переменными и без переопределения MAX_CANDIDATES / ARCHIVE_PAGES:

```bash
TRUSTED_EGRESS_PROXY=true .venv/bin/python -m backend.app.cli --archive --force-sources
.venv/bin/python -m backend.app.cli --audit
./scripts/start.sh
```

Для изоляции установлен другой `DATABASE_URL`; при старте использован свободный
порт 8002. Прочие параметры имеют значения по умолчанию: MAX_CANDIDATES=30,
ARCHIVE_PAGES=20. Scheduler включён; сервер проверен и остановлен до следующего
часового запуска, чтобы он не менял результат отдельной CLI-проверки.

Результат: 11 источников, 147 найденных URL, 60 обработанных кандидатов,
39 rejected, 18 pending, 3 кандидата-event, 0 опубликованных проектов.
Счётчик `events=6` отражает созданные записи мероприятий, которые могут
извлекаться также из статей с другим итоговым статусом кандидата. Ошибок источников/парсера в этом run нет;
`partial` объясняется отсутствием AI и pending-кандидатами.
После audit и старта сервера результат публикации тот же.
`/`, `/status`, `/api/health`, `/api/projects?period=all`, `/api/status` ответили 200.

| Проект | Состояние после этих трёх команд | Точная причина |
|---|---|---|
| Uzbekistan Airways | not_discovered | URL отсутствует в очереди: текущие списки не дали статью 2022 года |
| DMED UZ | not_discovered | URL отсутствует в очереди: текущие списки не дали статью 2025 года |
| KotibAI | queued, attempts=0 | URL найден в Spot startups, но не вошёл в первые 60 обработок |

Таким образом, даже KotibAI не гарантирован после *одного* ограниченного
запуска. Сообщённая пользователем одна карточка согласуется с последующей
обработкой очереди либо другой выборкой текущих страниц, но без его БД нельзя
утверждать, какой именно вариант произошёл.

`--archive` разрешает старые даты в текущих списках и очереди; он не задаёт
годовые окна обхода. `--force-sources` обходит расписание источников.
`--audit` не ищет статьи и не обрабатывает queued. Запуск API планирует следующий
часовой discovery, но не выполняет немедленно полный backfill.

коллектор или seed-конфигурацию. Оснований скрывать эти три статьи или ослаблять
фильтры не найдено.

## Команда годового backfill на новой базе

Следующая проверка использует отдельную базу, не удаляет рабочую и не копирует
Cloud-карточки. Лимиты совпадают с прежним отчётом Cloud:

```bash
(
  repro_dir=$(mktemp -d)
  export DATABASE_URL="sqlite:///$repro_dir/finder.sqlite3"
  export AI_API_KEY= OPENAI_API_KEY= SEARCH_API_KEY=
  export TRUSTED_EGRESS_PROXY=true MAX_CANDIDATES=200 ARCHIVE_PAGES=12
  .venv/bin/python -m backend.app.cli --backfill \
    --from-date 2022-01-01 --to-date 2026-09-30 \
    --report "$repro_dir/backfill.json"
  # Partial (exit 1) не означает, что сохранённые результаты потеряны.
  .venv/bin/python -m backend.app.cli --inspect-url \
    https://www.spot.uz/oz/2025/01/07/dmed
)
```

Для заполнения рабочей базы используется тот же `--backfill` без временного
DATABASE_URL. Достаточно данных для оценки карточек — не гарантия покрытия
всех проектов. Содержимое источников, их доступность, sitemap, версии кода,
настройки реестра, лимиты и прежняя очередь влияют на результат.

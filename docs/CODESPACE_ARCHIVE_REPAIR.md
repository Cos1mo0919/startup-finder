# Stage 1 — исправление старого архивного реестра в Codespace

7 октября 2026. Stage 1 не принят; Global не начинался.

## Подтверждённая причина

Пользователь проверил HEAD `24765df`, затем обновился до диагностического
`8945f4d` и прислал debug-отчёт из своего Codespace. У `spot-uz`, `spot-ru` и
`itpark`: `archive_configured=false`, `seed_archive_configured=true`,
`archive_matches_seed=false`, `archive_adapter=current_listings`.
Во всех пяти годовых runs 4–8 поле `coverage=[]`. Архивные sitemap не читались.

Код обновлён, но сохранённый Source Registry содержит прежние настройки.
`seed_registry(update=False)` добавляет отсутствующие источники, сохраняя
существующие, включая старые `options={}`. У прежних RSS Spot нет адаптера
архива; прежний collector молча использовал текущую RSS даже при `--backfill`.
Поэтому статьи 2022/2025 не обнаруживались. Повторный drain не ищет новые URL.
Это расхождение состояния реестра, не отказ fallback из-за отсутствия AI.
Предыдущая проверка совершенно пустой базы с новым seed не моделировала этот
путь обновления. Обычное обновление Git не заменяет настройки в SQLite.

`22 rejected` в присланном run 10 — число повторных отклонений
`outside_archive_window` именно в этом запуске; оно не является общим числом
rejected во всей БД. Четыре включённых search-профиля дают `requires_api_key`
и объясняют часть partial, но ключ не требуется для sitemap Spot.

## Исправление

`--repair-archive-config` добавляет исключительно отсутствующий ключ
`options.archive` из текущего seed, если ID, канонический URL и collection_method
совпадают. Существующий ключ archive (включая намеренно пустой), изменённый
endpoint и пользовательский адаптер не перезаписываются. Остальные options,
enabled, priority, check_frequency, reliability и health остаются прежними.
Команда идемпотентна; возможен `--source-id spot-uz` для одного источника.
Ни проекты, ни кандидаты, ни их даты не удаляются и не переоцениваются этой командой.

Архивный запуск при отсутствующем ожидаемом адаптере теперь сообщает
`archive_configuration_missing` / `NEEDS_CONFIG`; эта ошибка входит в
configuration_errors и имеет узбекскую подпись в status. Текущий RSS больше
не выдаётся за годовой обход для такого источника. Обычный свежий поиск
сохранён. Для источников, у которых seed вообще не предусматривает архив,
прежнее поведение текущих списков остаётся.

## Команды для существующей базы Codespace

```bash
git pull --ff-only
.venv/bin/python -m backend.app.cli --repair-archive-config
# Отдельный полноценный bounded run с явно указанными лимитами прежней проверки:
AI_API_KEY= OPENAI_API_KEY= SEARCH_API_KEY= MAX_CANDIDATES=200 ARCHIVE_PAGES=12 \
  .venv/bin/python -m backend.app.cli --backfill \
  --from-date 2022-01-01 --to-date 2026-09-30 --report /tmp/archive-repaired.json
.venv/bin/python -m backend.app.cli --debug-report --report /tmp/finder-debug-after.json
```

Сетевую настройку используйте действующую для своей среды; в управляемой Cloud
проверке требуется `TRUSTED_EGRESS_PROXY=true`. Частичный статус возвращает 1,
поэтому не связывайте последующую диагностику через `&&` с backfill.
Увеличение лимита обработки не меняет качество допуска. ARCHIVE_PAGES=12 здесь
задан для точного повторения прежней выборки: при 20 выбираются другие недели
sitemap, а не строго расширенный набор. Это ограниченный обход, а не гарантия
полного покрытия. Очередь и pending — разные состояния; один ограниченный drain
не обещает обработать всю базу.

Старые включённые search-профили останутся включёнными и продолжат сообщать
`requires_api_key` без ключа. Эта команда не переключает их и не включает
выключенные университеты. `--update-sources` для данного исправления не нужен:
он меняет гораздо больше настроек.

## Дополнительная ошибка малой очереди

В отдельном контроле с текущим seed и лимитами 30/20 KotibAI был найден в
текущем списке ещё во время окна 2022 года, но не вошёл в бюджет обработки.
При последующем обнаружении в окне 2026 его queued-запись сохраняла scope 2022.
Итог до поправки: `rejected: outside_archive_window`, хотя статья датирована 2026.

Исправлено только переназначение **необработанной queued-ссылки**, повторно
найденной в окне, которому соответствует её датированный URL. Например,
`/2026/03/10/kotibai` может перейти в окно 2026, а `/2022/07/19/...` не переносится
в 2026. Дата URL используется для маршрутизации очереди, не для подтверждения
публикации. После загрузки по-прежнему проверяется настоящая дата статьи:
тест с URL 2026 и публикацией 2025 остаётся rejected. Пороги и fallback неизменны.

### Текущий seed, обычные лимиты и один drain

Контрольный свежий запуск **после поправки queued**: MAX_CANDIDATES=30,
ARCHIVE_PAGES=20, `--backfill`, затем один `--drain --archive`.
Опубликованы **DMED и KotibAI**, а не обещанные безусловно три карточки.
До поправки аналогичный запуск публиковал DMED, а KotibAI ошибочно оставался
rejected со scope 2022; теперь его scope 2026, status published.

Итог после поправки: 1265 уникальных кандидатов — 2 published, 39 pending,
129 rejected, 3 event, 3 error, **1089 queued**. Один drain с бюджетом 60
обработок не исчерпывает исторический backlog. Количество найденных URL в
живых контрольных запусках также различается из-за доступности источников
(в предварительном окне 2023 случился HTTP 503); разница общих счётчиков
не приписывается поправке очереди.

Uzbekistan Airways при ARCHIVE_PAGES=20 **не обнаружен**, а не отвергнут
fallback: выбранные sitemap 2022 включают недели 11 июля и 1 августа,
пропуская `materials-oz-2022-07-18.xml`, содержащий статью 19 июля.
При ARCHIVE_PAGES=12 эта неделя включена. Алгоритм выборки не изменялся и
не подстраивался под известные названия. Поэтому для повторения трёх карточек
даны явные прежние параметры 200/12. Ограниченный backfill не обещает одинаковое
покрытие при любых настройках или исчерпывающий поиск.
